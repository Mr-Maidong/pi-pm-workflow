# 产品需求发布规范

本文件约束将产品类需求发布到阿里云云效时的正文模板与字段规则。PRD 可使用 Markdown 作为本地编辑源，但创建工作项时必须将已确认内容转换为 HTML 富文本，并以 `RICHTEXT` 格式写入云效。只有用户明确要求发布，并确认发布摘要后，才允许创建或更新云效产品类需求工作项。

## 发布边界

- 本技能负责把当前对话或本地 PRD 整理为完整 PRD，并发布为云效产品类需求。
- 普通 issue、缺陷、开发任务、设计方案和 ADR 不通过本流程发布。
- 发布前必须向用户展示 PRD 摘要、验收范围和云效字段，获得明确确认。
- 不得自动创建普通任务作为 PRD 的替代品。

## PRD 内容模板

云效产品类需求正文必须包含以下章节：

```md
## 1. 需求背景 & 目标

**背景**

- **目标**

-

## 2. 用户故事

-

## 3. 功能描述

### 主流程

### 异常/边界情况

## 4. 界面设计

> 此部分由用户手动补充，AI 必须保持为空。

## 5. 权限设计
```

## 云效字段映射

| PRD 内容   | 云效字段或规则                                   |
| ---------- | ------------------------------------------------ |
| PRD 标题   | 产品类需求标题，清晰描述用户价值                 |
| PRD 正文   | 将已确认 PRD 转换为 HTML 富文本，以 `RICHTEXT` 格式写入完整模板内容 |
| 工作项类型 | 产品类需求，不得使用普通任务替代                 |
| 优先级     | 发布前由用户确认；未确认时不得擅自提升优先级     |
| 负责人     | 发布前由用户确认，或沿用项目默认负责人并明确说明 |
| 状态       | 默认待处理；不得伪造待开发状态                   |
| 关联入口   | 在正文中明确入口应用、模块和相关本地文档         |

## 发布检查清单

- [ ] 已确认这是产品类需求，而非普通任务或缺陷
- [ ] 已使用项目领域术语，并检查项目内 `CONTEXT.md` 与相关 ADR（如存在）
- [ ] 已明确验收范围和不在范围内的内容
- [ ] 已向用户展示发布摘要并获得确认
- [ ] 发布后记录云效工作项编号和状态
